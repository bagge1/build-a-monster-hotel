## Q1. Core systems of a classic tycoon and of modern management-sim / hybrid tycoons, and how they work

### Takeaway
The classic tycoon is one loop. A player claims a plot, generators (droppers) produce value, value moves along conveyors through upgraders to a collector, cash builds up, and the player spends it on button pads that reveal the next items in a dependency tree. Rebirth resets all of this in exchange for a permanent multiplier. Modern hits keep that skeleton but change how income is produced. Steal a Brainrot uses income-per-second units bought from a shared conveyor and defended against raids. Restaurant Tycoon 2 uses NPC customers and staff plus a ratings system. The robust 2026 pattern is to keep value and ownership logic on the server and push the visible drop parts to the client.

### Cited Findings

**Classic loop and plots**
- The classic tycoon loop is droppers feeding conveyors, which feed collectors that convert items into currency. Players spend currency on buttons that unlock new droppers, better conveyors and upgraded collectors. — [creation.dev tycoon guide [Community]](https://www.creation.dev/learn/how-to-make-tycoon-roblox)
- Each player gets a base area. A "Tycoon Bases" folder holds the plots, and you should test that bases assign correctly and don't overlap. Purchase pads sit inside the base. Stepping on one with enough currency deducts the cost and reveals the item. Upgrades form a branching tree, not a single line. — [creation.dev [Community]](https://www.creation.dev/learn/how-to-make-tycoon-roblox)
- The template guide recommends tagging each plot with the owner's UserId so upgrades and cash are attributed to the right player. A dropper part above the conveyor clones a small currency part on a loop, and the conveyor pushes those parts toward the collector. Its estimated build time is 3–5 hours at beginner level. — [creation.dev tycoon template [Community]](https://www.creation.dev/templates/tycoon-template)

**The "cash value on the part" pattern**
- Droppers are timed spawners. They create a part every few seconds, give it a value attribute and drop it onto a conveyor. Upgraders increase the value of resources passing over them. Collectors detect touches, read the value attribute, add it to the owner's cash and destroy the part to free memory. — [creation.dev [Community]](https://www.creation.dev/learn/how-to-make-tycoon-roblox)
- A DevForum dropper class reads its drop rate from attributes and clones a template from ServerStorage on a loop. This is the typical server-side dropper implementation. — [DevForum "Very odd behaviour for the droppers" [Community]](https://devforum.roblox.com/t/2643484)
- The creation.dev guide still names the legacy **BodyVelocity** for scripted conveyors, or a moving texture. — [creation.dev [Community]](https://www.creation.dev/learn/how-to-make-tycoon-roblox). (Engineering inference: BodyVelocity is a legacy BodyMover. Modern conveyors usually set `AssemblyLinearVelocity` on an anchored belt part and animate a texture for the visual. Treat the tutorial's choice as dated.)

**Why server-spawned drops are the classic performance and exploit problem**
- A tycoon lag thread describes the server hanging for 4–5 seconds and then releasing a burst of money bricks that jam conveyors. The reply blames kits that create and remove many models at once and recommends the MicroProfiler and the F9 console. A commenter proposes the standard fix: droppers run on the server and credit money, while each client spawns and manages its own capped set of visual bricks (around 200 per client). — [DevForum "Tycoon Lag – How to fix?" [Community]](https://devforum.roblox.com/t/tycoon-lag-how-to-fix/387741)
- With StreamingEnabled, a "server creates drops, client builds visual copies" design breaks for drops on other plots that stream in without a client counterpart. A suggested workaround is a client script per base, with the base model's `ModelStreamingMode` set to Nonatomic so the RemoteEvent and script don't load until the base does. Drops can linger after a base streams out and back in, so cleanup is required. — [DevForum "Issue with StreamingEnabled in Tycoon Game" [Community]](https://devforum.roblox.com/t/issue-with-streamingenabled-in-tycoon-game/3884084)
- General pattern from a related thread: the server keeps only the data it needs (positions, logic), and models, parts and effects are handled by the client. — [DevForum "Client side rendering confusion" [Community]](https://devforum.roblox.com/t/client-side-rendering-confusion/2701037)
- Roblox's security guidance says exploiters can take network ownership of their character and of unanchored parts, and can trigger `Touched` or ProximityPrompt events "at any range or frequency." — [Roblox Security tactics [Official]](https://create.roblox.com/docs/scripting/security/security-tactics)

**Rebirth / prestige (Roblox tycoon convention)**
- Rebirth resets the base and currency in exchange for a permanent multiplier, for example 2x on the first rebirth and 3x on the second. The guide recommends starting with 5–10 rebirth levels and aiming for the second run to take about 70% of the first run's time. — [creation.dev [Community]](https://www.creation.dev/learn/how-to-make-tycoon-roblox)

**Steal a Brainrot (2025–26 hybrid: conveyor shop, base income, PvP raiding)**
- Players start with $100 and build income from "brainrot" units that each generate currency per second. Example late-game values: Strawberry Elephant costs $500B and earns $250M/s, Dragon Cannelloni $125B and $100M/s, La Grande Combinasion $1B and $10M/s. Selling a unit returns 50% of its price. — [BuffGet economy article [Community]](https://buffget.com/news/steal-a-brainrot-economy-conveyor-sniping-vs-base-raiding)
- A central conveyor cycles units for purchase from common to rare. The cheapest early units earn about $1–2 per second. — [allthings.how guide (search snippet) [Community]](https://allthings.how/?p=6441)
- Rarity-timed spawns: Legendary units spawn on the belt every 5 minutes and Mythic every 15 minutes. Mutations multiply income: Golden 1.25x rising to 2x in later seasons, Diamond 1.5x to 3x, Rainbow 1.5x to 10x, Cursed 9x. Completing an index adds +0.5x to the money multiplier. "Admin Abuse" events (Tuesdays and Saturdays, 30–45 minutes) give 10x luck on high-tier spawns. — [BuffGet [Community]](https://buffget.com/news/steal-a-brainrot-economy-conveyor-sniping-vs-base-raiding)
- Raiding: the base-lock timer starts at 30 seconds and grows by 10 seconds per rebirth. Base capacity is about 26–27 slots depending on season, and the maximum rebirth is 17–18. Defensive and offensive tools include traps, turrets and Medusa's Head. — [BuffGet [Community]](https://buffget.com/news/steal-a-brainrot-economy-conveyor-sniping-vs-base-raiding)
- Carrying a stolen unit slows the thief, disables their items and alerts the owner, and one hit returns the unit to its base. — [allthings.how / playnews search snippets [Community]](https://www.playnews.gg/en/guides/steal-a-brainrot-roblox-the-complete-strategy-rebirth-and-tier-list-guide-for-july-2026)
- Note: community sources disagree on several Steal a Brainrot numbers (unit costs, lock times) across seasons. Treat all values as version-specific. — [search synthesis across allthings.how, deltiasgaming, BuffGet [Community]](https://buffget.com/news/steal-a-brainrot-economy-conveyor-sniping-vs-base-raiding)

**Restaurant Tycoon 2 (management sim with NPC AI)**
- Waiters serve the dining room, and happier staff level up faster. The restaurant is rated out of five stars across six categories: food, service, design, popularity, experience and eco. Higher ratings bring in more customers, who are also pickier. — [ScreenWise review [Community]](https://screenwiseapp.com/media/restaurant-tycoon-2-game)
- An in-game day lasts about 8 real minutes. Customers order, eat and pay, and a daily summary reports satisfaction. — [Narcosis beginner guide, July 2026 [Community]](https://www.narcosis-the-game.com/?p=2002)
- In a quest, classic NPC customers want cheeseburgers, and after 45 burgers they also want drinks. Waiters may serve other customers first, so the player cooking directly speeds things up. This shows a priority-queue, task-based staff AI. — [ItemLevel [Community]](https://itemlevel.net/how-to-get-all-5-tokens-in-restaurant-tycoon-2-roblox-the-class-hub/)

**Offline and idle income (idle-game reference)**
- Egg, Inc. caps offline earnings at 2 hours. That is a common design limit that keeps offline income from replacing active play. — [Pecorella, Math of Idle Games Part III](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-iii)

### Inferences (engineering inference unless noted)
- **Plot claiming:** Assign plots on the server, either automatically on `PlayerAdded` or through a "claim" pad, and store `Owner` on the plot as an attribute or an ObjectValue. Free the plot and clear its contents on `PlayerRemoving`. Spawn or teleport the player's character to their plot. When saving, store plot-relative data (purchased button IDs, placed-object CFrames relative to the plot origin) so a player can load into any plot.
- **Buttons with dependency chains:** Model each purchasable as data (ID, price, currency, `requires = {ids}`, the model to reveal) rather than as scripts inside each button. Tag pads with CollectionService. One server module listens for touches or prompts, validates ownership, price and dependencies, then reveals the item and the newly unlocked buttons. Clients only show button visibility and price labels. Purchased IDs are the save data, and the plot is rebuilt from them on load.
- **Drops:** The robust 2026 pattern is a value-only server simulation. The server ticks each owned dropper, computes `value * upgraderMultipliers` (upgraders the drop would pass are known statically from the layout), and credits the collector's pending cash after the known travel time. It fires a compact event to nearby clients, which spawn pooled, non-colliding visual parts. This removes server physics, Touched exploits and replication cost. If real physics drops are kept, anchor or set server network ownership, cap drops per plot (the community guidance is about 30–50 per plot from [creation.dev template [Community]](https://www.creation.dev/templates/tycoon-template)), and never trust a drop's value attribute without a server-side lookup.
- **Collectors and auto-collect:** Cash usually piles up in a collector "bank" and the player claims it by stepping on a pad. This adds a return-to-base loop and supports an "auto-collect" gamepass. Apply bank and cash changes only on the server.
- **Owner-only walls and doors:** The server checks `Owner` before teleporting or letting a player through. Purely client-side CanCollide doors are cosmetic because an exploiter can remove them, so a server-side check that ejects intruders or shields the bank is required for anything with stakes, such as raiding games.
- **Leaderstats:** A `leaderstats` folder of IntValue or NumberValue objects is still the built-in way to show values on the player list. Use it for display only, mirrored from authoritative server data. Large values (above 2^53) should be shown as a formatted StringValue.
- **Cash formatting:** The standard suffix ladder is K (1e3), M (1e6), B (1e9), T (1e12), Qa (1e15), Qi (1e18), Sx (1e21), Sp (1e24), Oc (1e27), No (1e30), Dc (1e33), followed by Ud, Dd, Td and so on. Many simulators switch to scientific notation after about 1e36 or offer it as a setting.
- **Placement and build systems (hybrid tycoons):** Use a client-side preview with grid snapping (round the position relative to the plot origin to the grid size, and rotate in 90-degree steps). Send `(itemId, gridX, gridZ, rotation)` to the server, never a raw CFrame. The server re-validates bounds, overlap (spatial query or an occupancy grid kept in data), ownership and price.
- **NPC customers (management sims):** Keep NPC state machines on the server (spawn, then queue, seat, order, wait with patience decay, eat, pay or leave angry) with simple pathing. Render NPCs on the client where possible. Throughput is capped by staff and seat counts, so upgrades raise those caps. This matches the RT2 rating and staff loop above.
- **Raiding (Steal a Brainrot-style):** Base lock and shield timers, server-validated "carry" state (the stolen unit is attached and the carrier is debuffed), a return-on-hit rule and an owner alert are all server rules. Lock duration scaling with rebirth (+10 s per rebirth, per BuffGet) gives progression-based defense.

## Q2. Must-have feature checklist for a 2026 tycoon, and what is optional

### Takeaway
Little primary evidence ranks tycoon features. The checklist below combines Roblox's own platform capabilities (saving, monetization, notifications, rewarded ads, regional pricing) with community pacing guidance. Server-validated purchases, robust session-locked saving, a rebirth loop, a mobile-first UI, gamepasses and dev products with correct receipts, and daily or return hooks are table stakes. Trading, PvP raiding, NPC simulation and placement editors are differentiators.

### Cited Findings
- The community guide says a 2x-currency gamepass priced at 99–199 Robux converts best. — [creation.dev [Community]](https://www.creation.dev/learn/how-to-make-tycoon-roblox)
- Roblox takes a flat 30% marketplace fee on game passes and developer products. Regional Pricing auto-converts a base price into local Robux amounts. — [generalistprogrammer pricing guide [Community]](https://generalistprogrammer.com/tutorials/roblox-game-pass-pricing-guide)
- At RDC 2025, Roblox said Regional Pricing had launched for passes and would expand to all in-experience item types, and that Creator Rewards and Rewarded Video Ads had launched. — [Roblox RDC 2025 newsroom [Official]](https://about.roblox.com/newsroom/2025/09/roblox-rdc-2025)
- Experience Notifications: `ExperienceNotificationService:PromptOptIn()` shows an in-experience opt-in modal. Always call `CanPromptOptInAsync()` first, because eligibility depends on factors like age and whether the player already opted in. Notifications can carry launch data, for example to route a player to a location when they join. — [ExperienceNotificationService reference [Official]](https://create.roblox.com/docs/reference/engine/classes/ExperienceNotificationService); [Experience Notifications guide [Official]](https://create.roblox.com/docs/cloud-services/experience-notifications)
- Rewarded video ads grant a developer product through `ProcessReceipt` only after the full ad is watched. Use `GetAdAvailabilityNowAsync(Enum.AdFormat.RewardedVideo)` to hide the button when no ad is ready. — [Rewarded video ads guide [Official]](https://create.roblox.com/docs/production/promotion/rewarded-video-ads)
- Pacing: price upgrades at about 2–5 minutes of current earnings, treat waits over 10 minutes as too slow, and plan 30–50 upgrades for the first playthrough. — [creation.dev [Community]](https://www.creation.dev/learn/how-to-make-tycoon-roblox)
- Cross-platform input: the Input Action System lets you define actions (InputAction inside an InputContext) with bindings for several hardware inputs at edit time. Contexts can be enabled or disabled and can "sink" input by priority. Each action should have a binding for gamepad, keyboard/mouse and touch. — [Input Action System docs [Official]](https://create.roblox.com/docs/input/input-action-system)

### Inferences (engineering and design inference)
**Must-have (2026 baseline)**
1. Session-locked saving (ProfileStore or an equivalent) with autosave, save on leave and on shutdown, data versioning and migrations (see Q4).
2. Server-authoritative economy: every purchase, collect and rebirth validated on the server.
3. Rebirth or prestige with a visible multiplier and a clear "next rebirth" goal.
4. Mobile-first UI (most Roblox players are on phones; this market figure is not sourced here, see Gaps). Use large tap targets, `UIScale` or scale-based sizing, safe-area awareness, and test at phone resolutions plus a gamepad pass for console.
5. Onboarding or tutorial: an arrow or beam to the first button and the first collect, done in under 60 seconds.
6. Monetization: core gamepasses (2x cash, auto-collect, VIP or faster droppers), consumable dev products (cash packs, boosts) via a correct `ProcessReceipt`, optional rewarded ads, and regional pricing enabled.
7. Daily or session rewards and playtime gifts, plus Experience Notifications opt-in for return hooks.
8. Codes system, with codes validated and redeemed on the server and recorded per player to prevent double redemption.
9. Leaderboards (OrderedDataStore for all-time, MemoryStore sorted maps for live or seasonal boards).
10. Group join reward (`Player:IsInGroupAsync`) and favorite or like prompts. These are common, but platform rules on incentivizing engagement should be checked.
11. Settings: music and SFX volume, low-graphics toggle, hide other players' drops, number format.
12. Juice and feedback: purchase sounds, particles, tweens, floating "+$X" text, cash counter animations, done client-side.

**Optional / differentiators**
- Pets or helpers that multiply income, quests and achievements, an index or collection book, offline income (with a cap, for example about 2 hours per the Egg, Inc. precedent), trading (needs session locking and atomic swaps), PvP or raiding, visiting other bases, placement or build editor, NPC customer simulation, seasonal events, limited-time "admin abuse" style live events.

- No authoritative figure was retrieved in this pass for the share of players on mobile (likely covered by the market researcher).
- Roblox policy specifics on rewarding group joins, likes and favorites were not verified in this pass.

## Q3. Economy design math

### Takeaway
Use exponential costs (`cost_n = base * r^n`) against linear or step-multiplied production, so each purchase's payback time rises steadily. Milestone and rebirth multipliers then reset the curve. Rates around 1.07 per unit are the canonical idle-game reference (AdVenture Capitalist). Prestige currency is usually a sublinear root of lifetime earnings, and the root exponent sets how many times more you must earn to double prestige (4x for sqrt-style, 8x for cube root, 128x for a 1/7 power). Luau doubles are exact only up to 2^53 (about 9 Qa), so either accept float imprecision up to about 1.8e308 or use a big-number library.

### Cited Findings
**Core formulas (Pecorella / Kongregate, republished on Game Developer)**
- Next cost: `cost_next = cost_base × rate_growth^owned`. Production: `production_total = (production_base × owned) × multipliers`. — [Math of Idle Games Part I](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-i)
- Bulk cost of n units with k owned: `cost = b × r^k × (r^n − 1)/(r − 1)`. Max affordable with currency c: `max = floor( log( c(r − 1)/(b·r^k) + 1 ) / log(r) )`. These only work for simple exponential growth without shifting costs or exponents. — [Part I](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-i)
- AdVenture Capitalist Lemonade Stand: `rate_growth = 1.07`, `cost_base = 4` (technically 3.738 because the first stand is free), `production_base = 1.67/sec`. At 10 owned the next cost is about 7.87 and production is 16.7/sec. A x2 multiplier triggers at 25 and 50 owned. — [Part I](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-i)
- "Optimal" buying means best income-to-cost ratio. The newest generator is "nearly always dominant" once affordable, which removes choice. Varying multiplier milestones makes different generators the priority over time. — [Part I](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-i)
- The AdCap wiki confirms the Lemonade Stand row (initial cost 3.738, coefficient 1.07, cycle time 0.6 s, revenue 1, productivity 1.67/s). Cycle time halves at 25, 50, 100, 200, 300 and 400 owned (up to 12 halvings), and the coefficient differs per business. — [AdVenture Capitalist Wiki (search snippet) [Community]](https://adventure-capitalist.fandom.com/wiki/Businesses)
- Part II of the series covers alternate growth models (not fetched in this pass). — [Math of Idle Games Part II](https://www.gamedeveloper.com/disciplines/the-math-of-idle-games-part-ii)

**Prestige formulas (Part III)**
- Realm Grinder: `p = (sqrt(1 + 8·c_M/1e12) − 1)/2`, the inverse of `c_M = 1e12·p(p+1)/2`. Doubling prestige needs about 4x the previous run's earnings. — [Part III](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-iii)
- AdVenture Capitalist: `p = 150·sqrt(c_L/1e15)` on lifetime earnings. Doubling needs about 3–4x earnings, and players can reset repeatedly at the same point for diminishing gains. — [Part III](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-iii)
- Cookie Clicker: `p = cbrt(c_L/1e12)`, so doubling needs about 8x earnings. — [Part III](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-iii)
- Egg, Inc.: `Δp = (c_R/1e6)^0.14` on this run's earnings, so doubling needs about 128x (2^7). Offline is capped at 2 hours. — [Part III](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-iii)
- Design advice: use a "bumpy" rhythm of fast and slow stretches, and treat doubling targets (4x, 8x, 128x) as the benchmark when tuning a prestige curve. Spreadsheet models are rough because players keep playing past milestones. — [Part III](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-iii)

**Roblox-tycoon-specific pacing heuristics** (community, unverified)
- Upgrade price of about 2–5 minutes of current earnings, maximum wait about 10 minutes, 30–50 upgrades in run one, rebirth multipliers of 2x then 3x, second run about 70% as long as the first. — [creation.dev [Community]](https://www.creation.dev/learn/how-to-make-tycoon-roblox)

**Big numbers in Luau**
- EternityNum is the best-known big-number module for Roblox incrementals. It handles values like 1e3003 with suffix notation, and posts describe a range up to 10↑↑2^1024. — [DevForum "How to use EternityNum" [Community]](https://devforum.roblox.com/t/how-to-use-eternitynum/2853584)
- GammaNum's author claims it is 30–100x faster than EternityNum at the same precision (self-reported). — [DevForum GammaNum [Author]](https://devforum.roblox.com/t/gammanum-up-to-100x-faster-than-eternitynum/3906397)

- InfiniteMath is also cited in DevForum comparison tables as built for numbers past 1e308 with suffix formatting. — [DevForum infinite number library thread (search snippet) [Community]](https://devforum.roblox.com/t/infinite-number-library/2593428)

### Inferences (math and design inference)
- **Doubling interval:** with growth r, cost doubles every `ln2 / ln r` purchases: r = 1.07 gives 10.2 purchases, 1.10 gives 7.3, 1.12 gives 6.1, 1.15 gives 5.0. Steeper rates make each repeatable generator saturate faster. Use about 1.07–1.10 for many-copies generators and 1.12–1.15 for few-copies upgrades. (The 1.07–1.15 range in the brief is consistent with AdCap's per-business coefficients, but only 1.07 was directly confirmed. See Gaps.)
- **Payback time:** for a purchase adding Δincome per second at price C, payback is `C / Δincome`. For a generator with linear production, unit n's payback grows as `r^n`. A milestone multiplier of m divides the payback of all owned units by m. Design each tier so payback starts around 30–60 s and climbs toward the 2–5 minute target (community heuristic) before the next milestone or tier unlock brings it back down.
- **Linear-button tycoons** (each button bought once, typical on Roblox): set `price_i = income_per_sec_before_i × T_i`, where T_i is the target wait in seconds, ramping from about 10 s for the first buttons to about 300 s near the end of a run. Then sum the wait times to check the time to complete a run (for example a 45–90 minute first run, shorter later runs).
- **Rebirth multiplier formulas** in common use: linear `mult = 1 + a·rebirths` (a = 0.5–1, which gives 2x and 3x at a = 1), or a root of lifetime earnings in the Pecorella style. Rebirth cost should grow faster than the multiplier, for example `rebirthCost = base·g^rebirths` with g around 2–4, so run length stays roughly flat or shrinks slowly (about 70% for run two per the community heuristic) instead of collapsing to zero.
- **Avoiding inflation:** use multiplicative sources sparingly (pets x gamepass x rebirth x events compound fast) and prefer additive stacking inside a category, multiplicative across categories. Cap or gate stacking (equip slots). Add sinks such as rebirth resets, consumables and cosmetic upgrades. Keep paid multipliers (2x cash) inside the curve's design, so tune assuming paying players have 2x and free players are still paced acceptably.
- **Number limits:** Luau numbers are IEEE-754 doubles. Integers are exact only up to 2^53 ≈ 9.007e15 (about 9 Qa), and the maximum is about 1.797e308. If the economy stays under about 1e15, plain numbers are exact. Up to about 1e308, plain doubles are fine for display and multiplication (precision loss is invisible at those magnitudes). Past 1e308, or if exact large integers matter (for example trading values), store a big-number representation such as `{mantissa, exponent}` or a library's serialized form. Store big numbers in DataStores as numbers or short strings, and guard against `inf`/`NaN` before saving (they are not valid JSON). That guard is an unverified recommendation.

## Q4. Roblox implementation best practices in 2026

### Takeaway
Treat the client as hostile. Every purchase, collect, rebirth and placement goes through a validated RemoteEvent handler that checks types, ranges, rate, ownership and price against server state. Save with a session-locking wrapper (ProfileStore is the current loleris library; ProfileService is unsupported). Prefer `UpdateAsync`, autosave on a jittered interval, and finish within the 30-second `BindToClose` window. Make `ProcessReceipt` idempotent by storing PurchaseIds in the player profile. For performance, keep drops visual and client-side, avoid server Heartbeat loops and mass instance churn, pool objects, and stream plots with Nonatomic or atomic models carefully. Knit is archived. Plain ModuleScripts plus a thin, typed remote wrapper (or buffer-based libraries such as Blink, Zap or Packet) is the 2026 norm. Tooling is Rojo plus Rokit, Wally (or pesde), luau-lsp, Selene and StyLua, with the new Luau type solver now generally released. Server Authority (fully released July 2026) is opt-in and mainly helps movement and physics cheats. A tycoon's economy still needs normal server validation.

### Cited Findings

**Security / anti-exploit**
- "Assume every piece of data sent from the client has been manipulated, fabricated, or sent with malicious intent." Exploiters can fire remotes "at any frequency with arbitrary arguments (besides the first Player argument)." — [Security tactics [Official]](https://create.roblox.com/docs/scripting/security/security-tactics)
- Purchase example: before approving, the server checks the item's true price, the player's money and the character's distance from the shop, all from server-held state. Threat-model each feature by asking what happens at 1,000+ calls per second and what the maximum legitimate rate is. Keep logic in ServerScriptService, never in replicated containers. — [Security tactics [Official]](https://create.roblox.com/docs/scripting/security/security-tactics)
- Knit's author recommends bespoke runtime checks on network data, for example `assert` that a value received over a RemoteFunction is a number. — [Knit ARCHIVAL.md [Author]](https://github.com/Sleitnick/Knit/blob/main/ARCHIVAL.md)

**Data stores: limits and practices**
- Use a small fixed set of data stores and one key per player (for example `User_{UserId}`) if it fits in 4 MB. Use stable IDs in keys. DataStore2 is legacy and should not be used for new experiences. — [Data store best practices [Official]](https://create.roblox.com/docs/cloud-services/data-stores/best-practices)
- Buffer data in memory and save periodically (the sample uses 180 s), on leave, on shutdown and at critical checkpoints such as purchases. Keep the interval shorter than any session-lock expiry. Stagger with random offsets and jitter. Retry with exponential backoff plus jitter, capped, and processed in order per key. Account for writes whose outcome is unknown. Prefer `UpdateAsync` when a write depends on the current value or multiple servers may write. Use versions instead of new keys per revision, and MemoryStore for temporary, fast-changing data. — [Best practices [Official]](https://create.roblox.com/docs/cloud-services/data-stores/best-practices)
- Server request budgets per minute (standard stores): Read `60 + numPlayers×40`, Write `60 + numPlayers×40`, List `5 + numPlayers×2`, Remove `60 + numPlayers×40`. Ordered store writes: `30 + numPlayers×5`. Experience-wide: Read `300 + CCU×40`, Write `300 + CCU×20`. Per-key throughput: 25 MB/min read, 4 MB/min write. Value limit 4,194,304 bytes. Key, store and scope names are 50 characters maximum. Storage limit is `500 MB + 1 MB × lifetime users` (latest versions only, compressed). Request queues hold 30 requests, and overflow fails with errors 301–306. — [Error codes and limits [Official]](https://create.roblox.com/docs/cloud-services/data-stores/error-codes-and-limits)
- Official reference implementation: the session lock is a GUID written atomically into key metadata in the same `UpdateAsync` call. Other servers abort if they see an unexpired foreign lock. The lock must be refreshed (autosave does this). Autosave defaults to 180 s with a per-player random offset. `BindToClose` saves everyone in parallel and "callbacks only have 30 seconds to complete." Roblox labels the code reference-only and not production-proven. — [Implementing player data and purchasing systems [Official]](https://create.roblox.com/docs/cloud-services/data-stores/player-data-purchasing)
- ProfileStore (loleris, October 2024) succeeds ProfileService. It provides session locking with server-to-server handoff (MessagingService resolves conflicts faster), a default autosave period raised from 30 s to 300 s, backoff and timeouts, per-key queues, `ProfileStore:MessageAsync()` replacing GlobalUpdates, Luau types, and an API of `ProfileStore.New`, `:StartSessionAsync()`, `:EndSession()`, `:Reconcile()`, `OnSessionEnd`, `OnSave`, `OnLastSave`, `OnAfterSave`. It is backward-compatible with ProfileService data and intended for player data, not leaderboards or global state. — [ProfileStore DevForum [Author]](https://devforum.roblox.com/t/profilestore-save-your-player-data-easy-datastore-module/3190543/)
- The ProfileService README says "This project is no longer supported" and "FOR NEW PROJECTS - USE ProfileStore." — [ProfileService GitHub [Author]](https://github.com/MadStudioRoblox/ProfileService)

**ProcessReceipt correctness**
- Return `PurchaseGranted` only after the benefit is granted and saved. Return `NotProcessedYet` when the player isn't in the server or a data store error occurs, and the receipt is retried when the player rejoins. The callback can be set only once, by one server script. — [MarketplaceService reference [Official]](https://create.roblox.com/docs/reference/engine/classes/MarketplaceService)
- Idempotency recipe: confirm the profile is loaded, check whether the PurchaseId is already in player data, grant in memory, record the PurchaseId, save, and return PurchaseGranted on success. If it was recorded but not yet saved, return NotProcessedYet. — [Player data and purchasing [Official]](https://create.roblox.com/docs/cloud-services/data-stores/player-data-purchasing)
- The MarketplaceService sample stores PurchaseIds via `UpdateAsync`, grant handlers "must never yield," and the page admits it "does not completely mitigate cross-server data failure scenarios." Use `ProcessReceipt`, not `PromptGamePassPurchaseFinished`, to grant dev-product benefits. — [MarketplaceService reference [Official]](https://create.roblox.com/docs/reference/engine/classes/MarketplaceService)

**Performance**
- Anchor parts that don't need physics. Set `CanCollide`, `CanTouch` and `CanQuery` to false where unneeded. Use Box collision fidelity on small anchored parts. Avoid the fixed 240 Hz physics mode. — [Improve performance [Official]](https://create.roblox.com/docs/performance-optimization/improve)
- Avoid per-frame Heartbeat work. Run income or upgrade checks on a timed loop, and split large tasks across frames. Creating or destroying large instance trees replicates and is network-heavy, so build or unlock plots in chunks. Send only changed data (on purchase, send the item, not the whole inventory). Create VFX and tweens on clients; server tweens replicate every frame. Pool frequently respawned objects. Disconnect Player connections and clear per-player tables on leave (or enable `Workspace.PlayerCharacterDestroyBehavior`). Reuse meshes, and lower `StreamingMinRadius` or `StreamingTargetRadius` if memory is tight. — [Improve performance [Official]](https://create.roblox.com/docs/performance-optimization/improve)
- Tycoon-specific: server-spawned money bricks cause lag spikes, and community advice is server-side value with client-side capped visuals. — [DevForum Tycoon Lag [Community]](https://devforum.roblox.com/t/tycoon-lag-how-to-fix/387741). For streaming interplay with per-plot client scripts and ModelStreamingMode Nonatomic, see [DevForum StreamingEnabled tycoon [Community]](https://devforum.roblox.com/t/issue-with-streamingenabled-in-tycoon-game/3884084)

**Server Authority (2026)**
- Full release on 2026-07-09. Enable it by setting `Workspace.AuthorityMode = Server`, which turns on `NextGenerationReplication`, `PlayerScriptsUseInputActionSystem`, `SignalBehavior = Deferred`, `StreamingEnabled` and `UseFixedSimulation`. Custom gameplay must use `BindToSimulation` and `InputAction`. It is opt-in, and staff say it will always be a choice. Known limits include 8 animation tracks per Animator, 64 attributes per instance, RemoteEvents not synchronized with the shared timeline, and higher server utilization. It stops injected movement (for example speed hacks), but your scripts still define what is legal. — [Full Release DevForum post [Official]](https://devforum.roblox.com/t/full-release-ship-fair-and-competitive-games-with-server-authority/4727993); [Roblox newsroom, July 2026 [Official]](https://about.roblox.com/newsroom/2026/07/creating-responsive-cheat-resistant-games-roblox-server-authority)
- Client prediction and rollback: the client re-simulates when the server state at a timestamp differs. Mispredictions are unavoidable for things like player collisions. — [Server Authority tech deep dive [Official]](https://devforum.roblox.com/t/server-authority-tech-deep-dive-engineering-insights/4624565)
- One developer reports input delay scaling with player count at high ping (unconfirmed by Roblox). — [DevForum bug report [Community]](https://devforum.roblox.com/t/server-authority-input-delay-scales-with-player-count-at-high-ping/4763481). Mirage is a community library for lightweight prediction of non-physics data such as inventory and counters. — [Mirage [Author]](https://devforum.roblox.com/t/release-a-free-solution-to-ping-for-server-authoritative-data-introducing-mirage/4757963)

### Inferences (engineering inference)
- **Remote handler template (all tycoon actions):** (1) type-check every argument (`typeof(x) == "string"`, numbers finite and not NaN, integers where expected), (2) reject anything not in a server-side lookup table (item IDs, button IDs), (3) check plot ownership and that the player's data is loaded, (4) check per-player rate limits (token bucket, for example 10 actions/s with a burst of 20) and debounce, (5) check price and dependencies from server data, never from the client, (6) mutate the authoritative profile, then replicate the minimal delta to the client. Never accept a price, amount or multiplier from the client.
- **Collect and Touched:** for the collector "bank" pad, server-side `Touched` is acceptable if you also verify distance and character state, but `GetPartBoundsInBox`/`GetPartsInPart` polling or a ProximityPrompt (with distance verified on the server) is more predictable. Touched can be faked locally for client-owned parts, per the official note that exploiters can trigger Touched at any range.
- **Network ownership:** if any unanchored drop parts exist, call `part:SetNetworkOwner(nil)` so the server simulates them, or anchor and tween them client-side. Otherwise exploiters can teleport drops into collectors.
- **Data model:** `{ Version = n, Cash, LifetimeCash, Rebirths, Purchased = {[buttonId]=true}, Placed = {...}, Pets, Settings, PurchaseIds = {...last N}, CodesRedeemed, DailyStreak, LastLogin }`. Run migrations keyed on `Version` at load, before `Reconcile()`. Cap the PurchaseId history (for example the last 50–100) to bound size.
- **Leaderboards:** OrderedDataStore writes have a lower budget (`30 + numPlayers×5`/min per server), so update global boards on a slow cadence (for example every 60–120 s per server) and read the top-N periodically. Use MemoryStoreService SortedMap for live, seasonal or event boards.
- **Trading:** with ProfileStore, perform both sides inside one server where both profiles are session-locked and active, swap in memory, then save both. Never trade across servers without a two-phase commit, and log trades.
- **Streaming:** keep each plot as an Atomic or Persistent model per Roblox streaming modes, or follow the Nonatomic-plus-per-plot-client-script approach above. Client visuals must react to `StreamingEnabled` add and remove events (use CollectionService `GetInstanceAddedSignal` on tagged plots).
- **Server Authority for tycoons:** it is useful for raiding games (speed and teleport exploits during steals). Most purely economic tycoons don't need it and can avoid its overhead and constraints (64 attributes per instance, deferred signals).
- **Project structure without Knit:** `ServerScriptService/Server/init.server.luau` requires ordered service ModuleScripts (`DataService`, `PlotService`, `EconomyService`, `PurchaseService`, `RebirthService`, `MonetizationService`), each exposing `init()` and `start()`. Mirror this on the client with controllers. Remotes are declared in one typed module, or generated by Blink or Zap from an IDL so both sides share types.
- **Mobile and console:** use Scale-based UDim2 plus `UIAspectRatioConstraint`, `UIScale` driven by viewport size, and `ScreenGui.ScreenInsets` (CoreUISafeInsets). Keep tap targets at least about 44 px. Bind actions through the Input Action System for touch, gamepad and keyboard, and add gamepad selection (`GuiService.SelectedObject`) for console menus.
- **Testing:** use ProfileStore's mock or Studio's API access toggle so test data doesn't hit production keys. Unit-test economy formulas (cost and payback tables) with Lune outside Studio.

## Q5. Open-source tycoon frameworks, templates and Roblox's own tutorials

### Takeaway
No well-maintained, widely endorsed open-source tycoon framework (Rojo or Wally-based) turned up in this research, and no official Roblox tycoon template or tutorial was found on the Creator Hub. What exists are third-party beginner guides (creation.dev), paid script packs, and legacy free-model "tycoon kits." Their known weaknesses are server-spawned physics drops, per-button scripts and weak validation. A from-scratch, data-driven architecture is the better 2026 path.

### Cited Findings
- Search for a Creator Hub tycoon tutorial returned only third-party creation.dev material: a beginner guide of 3–5 hours covering plot assignment, a dropper and collector loop, button pads, and DataStore saving of cash and rebirths. — [creation.dev tycoon template [Community]](https://www.creation.dev/templates/tycoon-template)
- creation.dev advises capping parts per plot (about 30–50) and using Debris to clean up stray parts. Saving: load on join; save on leave, every 60–120 s and in BindToClose; wrap calls in pcall; consider session locking. — [creation.dev [Community]](https://www.creation.dev/templates/tycoon-template); [creation.dev guide [Community]](https://www.creation.dev/learn/how-to-make-tycoon-roblox)
- A paid itch.io "Roblox Tycoon Script Pack" provides Dropper, Conveyor and Seller modules plus a demo place. — [itch.io script pack [Community]](https://maxuno.itch.io/roblox-tycoon-script-pack)
- Legacy "tycoon kits" are blamed in DevForum threads for lag from creating and removing many models at once. — [DevForum Tycoon Lag [Community]](https://devforum.roblox.com/t/tycoon-lag-how-to-fix/387741)
- A GitHub search for "roblox tycoon framework rojo" surfaced only Rojo itself, no tycoon framework. — [Rojo GitHub](https://www.github.com/rojo-rbx/rojo)

### Inferences
- **What the community guides do well:** they teach the core loop quickly, explain value-on-part, and cover basic saving and rebirth.
- **What they do poorly (engineering inference):** server-side physics drops (lag and network-ownership exploits), Touched-based collectors trusting a part's attribute, legacy BodyVelocity, raw DataStore `SetAsync` without session locking, no `ProcessReceipt` idempotency, and logic spread across one script per button.
- **Recommended starting point:** a small Rojo project using ProfileStore (Wally), a typed remote module (or Blink/Zap), a data-driven item catalog (one ModuleScript table of buttons, prices and dependencies), a CollectionService-tagged plot template, and client-rendered drops.

### Gaps
- GitHub was not searched exhaustively (for example by the topics `roblox-tycoon` or `tycoon` with `luau`). Small open-source repos may exist but none were found or evaluated.
- The legacy Zednov/Berezaa free-model kits were not directly examined in this pass.
